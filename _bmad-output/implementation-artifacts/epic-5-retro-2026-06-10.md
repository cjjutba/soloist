## What Went Well

1. **The seam-first habit compounded a THIRD time — Epic 5 was a chain of clean drop-ins.** 4.4 built `resolveNotifiableRecipient` + a type-generic `createNotification` *for* this epic, so 5.2's `invoice.sent` fan-out was a near-clone of `handleShipPublished` with the mute gate already free. 5.1 built `InvoiceDocument` as a standalone presentational render *for* 5.2/5.3, so 5.2's Client view reused it verbatim and 5.3's PDF mirrored it. 5.1 reserved `pdf_blob_url` *for* 5.3, so 5.3 shipped with **no migration**. Each story spent a little to set up the next; the payoff landed every time.

2. **Money never touched a float path — across three surfaces.** `integer minor units + formatMoney/computeLineTotal` is the single money discipline, reused identically in the builder's live total, the premium document, the branded email, AND the PDF. The PDF and the screen *cannot* disagree because they call the same helpers. The 5.1 review hardened it (currency regex + try/catch so a junk code can't crash an RSC render; int4-overflow refine) and it held for the rest of the epic.

3. **The load-bearing ownership guard is now a reflex.** `invoice_scope`'s WITH CHECK only gates `tenant_id` for a freelancer ctx, so RLS alone never scopes a write to the engagement — the `getEngagement`/`getInvoice` + `engagementId` cross-check carried cleanly from 5.1 (create) into 5.2 (send/mark-paid) and 5.3 (the PDF route). The privacy boundary (drafts excluded at the **repository**, not just the UI) mirrored the `ship_updates` published-only read — a Client can never see a draft via the list, the view, the notification, or the PDF.

4. **Backstop-first discipline held (the Epic-2/3 habit).** Both migrations landed BEFORE the UI that needed them, with the isolation matrix grown in the same change — 5.1's `(ak)–(ao)` (incl. the client engagement-scoped read = the 5.2 path), 5.2's `(ap)/(aq)` (the `invoice_id` column rides the existing `notification_scope`, no new policy). The RLS seatbelt was fastened before anyone got in the car.

5. **Both Epic-4 seam-completions landed exactly where predicted — inside 5.2.** The notification center's invoice **label + link** (a pure `notificationPresentation` shared by the center + toaster) and the invoice **email through 4.3's `EmailShell`** were the two things the Epic-4 retro flagged for 5.2. Both done; the 4.4 global mute gated `invoice_sent` for free, as forecast.

## What Was Hard — and the Pattern in the Review Catches

The adversarial review earned its keep on every story, and the **signature was consistent with Epic 4's**: not happy-path logic bugs, but **degradation at the edges** — a poison value, a lifecycle race, an infra sharp edge. The high-risk logic (atomic numbering, money float-safety, the ownership guards, RLS) was clean in all three; the fixes were the cracks around it.

- **5.1 — a poison value / DoS.** A length-3 but non-letter `currency` (`"P!P"`) passed Zod and then threw a `RangeError` in `Intl.NumberFormat` at RSC render — a persistent 500 on the documents page on every load. Fix: a real 3-letter regex + a `formatMoney` try/catch. (+ int4 overflow, + the builder silently dropping a half-filled line = an under-bill risk.)
- **5.2 — a lifecycle race the sibling didn't have.** `handleShipPublished` skips the email unless `state==='published'` — safe, because `published` is *terminal*. The faithful mirror (`status !== 'sent'`) was **wrong** for invoices: `sent` is NOT terminal, so a freelancer marking a Sent invoice Paid before the async fan-out ran would **suppress the legitimate email**. Fix: skip only if gone/still-draft; `sent` OR `paid` both email. *(The lesson: a mirrored pattern must be re-checked against the new entity's lifecycle, not copied.)*
- **5.3 — two infra sharp edges.** (a) A **deterministic Blob path without `allowOverwrite`** (default false) → "blob already exists" on a concurrent first-download or an orphaned `put`, wedging the invoice into a **permanent, unrecoverable 503** the lazy cache can't self-heal. Fix: `allowOverwrite: true`. (b) react-pdf's `<Image>` fetches the logo with **no timeout** — a broken/slow Tenant logo Blob would 503 or **hang the function** to its wall-clock limit. Fix: pre-fetch the logo myself (5s timeout) → data-URL, graceful text fallback.

**Lesson (Winston):** this epic added a new edge to the pattern — **the tooling itself has sharp edges**, not just email clients and browser races. A malformed test image made react-pdf hang ~250s and starved the whole suite; `@vercel/blob`'s overwrite default turns a deterministic cache path into a footgun. *Reason about the library's failure mode, not just your own code.* The 3-layer review (one agent with NO context, one walking every branch against the real repo, one auditing the spec) caught the High-severity `allowOverwrite` bug that the unit test — which asserted the exact `put` arg shape — was structurally blind to.

## Technical Debt Status

- **(paid) Both Epic-4 seam-completions** — the invoice notification label/link + the invoice email. Closed in 5.2.
- **(new, accepted v1) The invoice PDF Blob is `access:"public"`** — an unguessable-but-bearer URL (the Tenant-logo precedent); the route is the authz gate to obtain it. Future hardening: a private blob + proxy-the-bytes if invoices ever need stricter control. Documented in 5.3.
- **(new, test-infra) PGlite per-file migration replay is a scalability smell.** ~10 test files each re-apply every migration in `beforeAll`; on a loaded shared machine the parallel setups starve and time out. We bumped `hookTimeout` (30s→60s) and ran serially as a band-aid. The durable fix is sharing one migrated DB across the suites — deferred (cross-cutting, not invoice work). Flag it before the suite grows much larger.
- **(ops, carried 4 epics) Sentry DSN** unset; the early all-repos "test engagement" candidates — clean up or archive.
