## What went well

1. **The extra-high code review caught a real, ship-blocking bug in nearly every story — pre-production.** This is the single biggest win:
   - **1.2:** Neon's `neondb_owner` has `BYPASSRLS` → RLS was *inert in prod* despite `FORCE`. Caught empirically (an unscoped Neon probe returned BOTH tenants), fixed with a `soloist_app` NOBYPASSRLS role + `SET LOCAL ROLE` per tx. **This would have been a cross-tenant data leak on launch.**
   - **1.3:** Better Auth returns a *synthetic non-persisted user* on duplicate email (anti-enumeration) → my code fed it to provisioning → FK crash + enumeration leak. Verified at the library source, fixed with a `userExists` check.
   - **1.6:** SVG logos = active-content stored-XSS on a public blob origin → dropped SVG (PNG/JPG only).
   - **1.7:** `afterEmailVerification` re-fires on email changes → it was resetting `tenants.activated_at` → made `activateTenant` idempotent.
2. **The RLS isolation core (1.2) held across every later story.** The `withTenant` choke point + the regression test (an unscoped read must fail closed) caught nothing regressing — provisioning, branding, and account flows all stayed scoped. The ESLint guard (no raw db/schema outside `src/server/{db,auth}`) kept feature code honest.
3. **TDD on pure logic paid off.** The slug validator and the WCAG contrast guard were airtight (the contrast math was independently swept over 5,854 accents in review — every block-suggestion passes). Fast, deterministic, offline (PGlite for the DB layer).
4. **Decisive, surfaced load-bearing forks.** Two two-way-door decisions were made + confirmed rather than drifted into: (a) **path-based single-domain routing** (dropped per-tenant subdomains — avoided a Vercel nameserver delegation that risked CJ's live GoDaddy email); (b) **Better Auth core, not the org plugin** (kept the verified uuid RLS core; the plugin's members/invites are unused since identity is app-level). Both were the right call and are documented in `architecture.md`.

## What was hard (lessons)

1. **Bleeding-edge build-config archaeology.** Next 16 + Turbopack + the auth/blob ecosystem needed several non-obvious fixes: the `kysely@0.28.17` `overrides` (better-auth's kysely-adapter imports a constant 0.29 dropped, and Turbopack statically traces the unused sqlite branch), `serverExternalPackages`, `serverActions.bodySizeLimit`, `withSentryConfig`. **Lesson:** budget for build-config friction on cutting-edge Next; verify each new server-only dep builds under Turbopack early.
2. **Auth-library behavior ≠ docs.** The synthetic-duplicate-user and the email-change re-firing `afterEmailVerification` were both behaviors found by reading Better Auth's source, not its docs. **Lesson:** for security-adjacent library behavior, verify at the source.
3. **Scaffolding debt is real even when intentional.** 1.4 and 1.6 both left **dormant `/portal` code** (`requireClient` 404s everyone; branding application unreachable) because Clients/Engagements are Epic 2. Well-documented, but it means a chunk of Epic-1 code is untested-in-anger until Epic 2 activates it.
